# URTW — Universal Routing Toolset for Windows

[English](README.md) | Русский

Windows-компаньон URTA. Центр управления **Mihomo, sing-box, Xray, Zapret и
TG WS Proxy**: профили, приватные эндпоинты, вручную собираемые стандарты
маршрутизации, DNS каждого клиента и отдельный сплит браузера.
При открытии приложение только читает состояние.

## Быстрый старт

1. Скачай [ZIP релиза](https://github.com/Oqune/URTW/releases),
   [проверь GPG и SHA-256](docs/VERIFICATION.md), распакуй в удобную папку.
2. Запусти **URTW.bat**. Данные по умолчанию — **data/** рядом с приложением.
   **Settings → H** принимает путь, **K** открывает выбор папки.
3. **Cores → Enter** выбирает ядро, **I** устанавливает фиксированную официальную
   версию с проверкой SHA-256. Установка не запускает ядро.
4. **Profiles → F**: вставь путь к YAML Mihomo, JSON sing-box/Xray или WireGuard
   `.conf`. **N** открывает окно Windows. Можно выбрать файл до установки ядра:
   проверка будет pending. Исходник сохраняется без изменений.
5. Для своего конфига добавь эндпоинт в **Endpoints**, выбери/собери стандарт
   **Routing**, настрой ядро через **E** в Settings, нажми **G** в Profiles.
   Создаётся новый приватный файл. **V** проверяет, **S/X** запускает/останавливает.
6. **D** тестирует локальный прокси. **P** в Overview явно включает Windows Proxy.
   Для глобального TUN включи его в настройках поддерживаемого ядра, сгенерируй
   новый профиль и запусти его из терминала администратора.

Windows 10/11 x64 и сборка ARM64; ARM64 на физическом устройстве ещё не проверен.
Zapret/WinDivert работает только на x64. Для TUN и служб Zapret нужен администратор.
Сначала установи и проверь замену текущего VPN, затем переключай её вручную.
В публичном архиве нет личных профилей и сторонних бинарников.

## Интерфейс

**1–9, 0 / F1–F10 / Tab** — вкладки. Стрелки/PgUp/PgDn — списки.
**Q/Esc** закрывает UI, процессы продолжают работать. Минимум **60×18**.
В формах поддерживается вставка, Tab переключает поле, Delete очищает,
Enter сохраняет, Esc отменяет. Пароли и ссылки импорта скрыты.

| Вкладка | Основные клавиши |
|---|---|
| Overview | F/N конфиг; S/X ядро; P Windows Proxy; D диагностика; Y старый менеджер |
| Profiles | Enter выбрать; V проверить; C приватная копия для редактирования; R имя; Delete убрать запись; G генерация; O файл; L лог |
| Diagnostics | D тест; M локальный прокси/системный путь |
| Telegram | I установка; S/X запуск/стоп; L ссылка; G подключить; E порт; O настройки |
| Zapret | Enter оригинальный service.bat; I установка |
| Components | I/Enter установить выбранный компонент |
| Cores | Enter выбрать; E настройки; I установка; A адаптер; B локальный бинарник |
| Endpoints | A ссылка; W WireGuard; Enter выбрать; E заменить ссылку; R имя; Delete убрать |
| Routing | A стандарт; Enter выбрать; E правило; U/J порядок; B браузер; T остаточный маршрут; R имя; Delete убрать; G генерация; O PAC |
| Settings | E ядро/DNS; H/K папка; O открыть; B бэкап; R восстановление; A автозапуск |

Профили и настройки каждого ядра независимы. Выбор/редактирование не меняют
работающий конфиг. C создаёт новую приватную копию для Notepad. Удаление записи
не удаляет файл. Новая папка данных не переносит файлы и не останавливает старые
процессы; выбор запоминается рядом с exe. Приоритет: --root, URTW_HOME,
старый URT_HOME, сохранённая папка, portable data/, иначе LOCALAPPDATA.

## Маршрутизация

Импорт: WireGuard с одним peer, SOCKS5, HTTP(S), VLESS, Trojan; TCP/WS/gRPC,
TLS/REALITY. В новом профиле один выбранный эндпоинт. Подписки, балансировка и
сложные возможности доступны через нативный конфиг ядра.

Правила: `domain example.com proxy`, `process app.exe direct`,
`ip 192.0.2.0/24 block`. Маршруты direct/proxy/block. Порядок генерации:
локальные сети DIRECT → браузерные proxy-домены → правила по порядку → остаточный
маршрут. Поэтому браузерные домены идут перед process chrome.exe direct.
Отдельный [PAC браузера](docs/BROWSER.md) проксирует только выбранные домены,
остальные DIRECT. После изменения списка или порта сгенерируй профиль заново.
Для совпавшего домена PAC не обходит отказ прокси прямым подключением.

| Генератор | Mihomo | sing-box | Xray |
|---|---|---|---|
| Нативные профили | YAML | JSON | JSON |
| Перечисленные эндпоинты / WireGuard | Да | Да | Да |
| Правила процессов / TUN | Да / да | Да / да | Нативная интеграция |
| DNS IP / DoH | Да | Да | Да |
| DoT | Да | Да | Нативный профиль |

Порт, DNS, IPv6, уровень логирования и поддерживаемый TUN сохраняются по ядрам.
При выключенном IPv6 сгенерированный DNS использует IPv4. Семейства DNS зависят от ядра; неподдерживаемые варианты отклоняются. DNS настраивается внутри клиента; DNS Windows и метрики адаптеров не меняются.
Проверка синтаксиса не подтверждает доступность VPN. HTTP 403/429 — полученный
ответ, а не ошибка транспорта; завершённые ошибки тоже доводят прогресс до 100%.
System route может идти через уже включённый системный TUN.

## Расширение и восстановление

[Адаптеры других ядер](docs/ADAPTERS.md) содержат автора, лицензию, формат и
аргументы запуска/проверки. A импортирует адаптер, B устанавливает доверенный
локальный exe; затем выбирается нативный профиль. DLL положи рядом с ядром.

Бэкап включает секретные эндпоинты, копии профилей и Telegram, защищается ACL.
Восстановление требует остановки управляемых процессов, сохраняет текущее
состояние и создаёт новые файлы профилей. Исходники остаются. Бинарники, кэш и
задачи Windows в бэкап не входят. При переносе в новую папку адаптеры нужно
импортировать заново. Автозапуск — отдельная задача выбранного ядра; для TUN
создавай её от администратора. Windows Proxy, TG и Zapret автоматически не
включаются. Старые внешние задачи сохраняются.

URTW останавливает только точный PID с совпавшими путём exe и временем запуска.
Windows Proxy восстанавливается только при совпадении записанного состояния.
Секреты идут в backend через stdin; в аргументы процесса не попадают.
Настройки WS/DC/Cloudflare Telegram — в штатном трее; стратегии Zapret — в
оригинальном service.bat. Работающий внешний процесс остаётся под его управлением.
